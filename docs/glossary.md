## Data Science

กระบวนการใช้ข้อมูลเพื่อหาแบบแผน แล้วสร้างคำทำนายหรือข้อเสนอแนะที่ธุรกิจนำไปตัดสินใจได้

## Machine Learning

การเรียนรู้ของเครื่อง — ให้คอมพิวเตอร์เรียนรู้แบบแผนจากข้อมูลตัวอย่าง แล้วทำนายข้อมูลใหม่ได้โดยไม่ต้องเขียนกฎทีละข้อ

## Churn

การที่ลูกค้าเลิกซื้อหรือยกเลิกสมาชิก ในแล็บ FreshMart คอลัมน์ `Churn` เป็น 0 (อยู่ต่อ) หรือ 1 (เลิกซื้อ)  
ประมาณ 19.3% ของสมาชิกในชุดฝึกมี `Churn = 1`

## Lakehouse

พื้นที่จัดเก็บข้อมูลใน Microsoft Fabric ที่รวมไฟล์ข้อมูลต้นทาง (Files) และตารางวิเคราะห์ (Tables) ไว้ในที่เดียว (ใช้รูปแบบ Delta Lake)

## OneLake

ที่เก็บข้อมูลกลางขององค์กรบน Fabric — หลายเครื่องมือ (Spark, SQL, Power BI) อ่านสำเนาเดียวกันได้โดยไม่ต้องคัดลอกซ้ำ

## Medallion (Bronze / Silver / Gold)

ชั้นคุณภาพข้อมูลสามชั้น — แต่ละชั้นเป็น**สัญญา**ว่าข้อมูลนั้นเชื่อถือได้แค่ไหน:

1. **Bronze** — ข้อมูลต้นฉบับจากแหล่งกำเนิด (Raw Ingestion) เช่น `bronze.customers`
2. **Silver** — สะอาดและมีฟีเจอร์พร้อมวิเคราะห์ เช่น `silver.customer_features`
3. **Gold** — พร้อมใช้ธุรกิจ/รายงาน เช่น `gold.freshmart_predictions`

ในแล็บนี้ชื่อชั้นคือชื่อ **schema** ของ lakehouse เดียวกัน ไม่ใช่แค่คำนำหน้าตาราง  
ในองค์กรอาจแยก lakehouse ต่อชั้นได้ — สัญญาคุณภาพเหมือนกัน เส้นแบ่งทางกายภาพต่างกัน  
ดูรายละเอียดใน [M01](01-fabric-architecture.md#ทำไมชื่อ-schema-สำคัญต่อ-medallion)

## schema.table

ชื่อตารางแบบมี schema เช่น `bronze.transactions` หมายถึงตาราง `transactions` ใน schema ชื่อ `bronze`  
ในชุดแล็บนี้ schema `bronze` / `silver` / `gold` คือชั้น [Medallion](#medallion-bronze--silver--gold)  
ต้องเปิด **Lakehouse schemas** ตอนสร้าง lakehouse — เลือกได้ครั้งเดียว

## Notebook

สมุดทำงานที่มีทั้งคำอธิบายและโค้ดรันทีละเซลล์ ใช้สำรวจข้อมูลและฝึกโมเดลบน Fabric

## การสำรวจข้อมูลเบื้องต้น (Exploratory Data Analysis)

การดูสถิติ กราฟ ค่าว่าง และความสัมพันธ์ของตัวแปร **ก่อน** สร้างโมเดล เพื่อเข้าใจข้อมูลและจับปัญหา  
ในแล็บนี้คือเนื้อหาหลักของ Lab 1

## ฟีเจอร์ (feature)

คอลัมน์อินพุตที่โมเดลใช้ทำนาย เช่น อายุ ความถี่ซื้อ จำนวนครั้งที่ร้องเรียน  
อย่าใส่รหัสลูกค้า (`CustomerID`) หรือคอลัมน์คำตอบ (`Churn`) ลงในชุดฟีเจอร์ตอนฝึก

## เป้า (target / label)

คอลัมน์คำตอบที่ต้องการทำนาย เช่น “จะเลิกเป็นลูกค้าหรือไม่” (`Churn`)

## Data Wrangler

เครื่องมือใน Notebook ที่ช่วยทำความสะอาดและแปลงข้อมูลแบบมีหน้าจอ แล้วสร้างโค้ด Python ให้กด **Add code to notebook** เพื่อรันซ้ำได้

## MLflow

เฟรมเวิร์กโอเพนซอร์สสำหรับติดตามการทดลองโมเดล บันทึกพารามิเตอร์และเมตริก และจัดเวอร์ชันโมเดล  
Microsoft Fabric รองรับ MLflow ในตัว — ไม่ต้องติดตั้งเซิร์ฟเวอร์แยกสำหรับแล็บนี้

## Experiment / Run

- **Experiment** — กล่องรวมผลการทดลองที่เกี่ยวข้องกันใน Workspace  
- **Run** — การรันโค้ดฝึกโมเดลหนึ่งครั้ง พร้อมค่าตั้งและคะแนนวัดผล

## Model Registry

ที่เก็บโมเดลที่ผ่านการคัดเลือก พร้อมหมายเลขเวอร์ชัน เพื่อนำไปทำนายซ้ำได้  
ในแล็บนี้ชื่อโมเดลคือ `freshmart-churn-model`

## โมเดลเส้นฐาน (baseline)

โมเดลแรกที่ใช้อ้างอิงเปรียบเทียบ เช่น Decision Tree ใน Lab 3 — ไม่จำเป็นต้องเป็นโมเดลที่ดีที่สุด แต่ใช้เป็นจุดเทียบ

## โมเดลที่เลือกใช้ (champion)

โมเดลที่ได้คะแนนดีที่สุดจากการเปรียบเทียบ และถูกลงทะเบียนเพื่อนำไปทำนายจริง เช่น Random Forest ใน Lab 3

## ลายเซ็นโมเดล (model signature)

สัญญาว่าโมเดลรับคอลัมน์อะไร ชนิดข้อมูลอะไร และคืนผลแบบใด  
จำเป็นก่อนใช้ฟังก์ชัน PREDICT — ลำดับและชื่อคอลัมน์ต้องตรงกับตอนฝึก

## feature_params.json

ไฟล์พารามิเตอร์จาก Lab 2 ที่เก็บค่า median / min / max ที่คำนวณจาก**ชุดฝึก**  
Lab 4 ต้องใช้ไฟล์นี้แปลงชุดทำนาย — ห้ามคำนวณสเกลใหม่จากชุดทำนาย 200 คน

## PREDICT

ฟังก์ชันใน Fabric ที่เอาโมเดลที่ลงทะเบียนแล้วไปทำนายข้อมูลจำนวนมากบน Spark  
มักเรียกผ่าน `MLFlowTransformer` ใน notebook

## การทำนายเป็นชุด (batch scoring)

การทำนายหลายแถวตามรอบเวลา (เช่น ทุกคืน) ไม่ใช่ตอบทันทีทีละคำขอแบบ real-time

## จุดตรวจ (verification)

ในแล็บหมายถึงเกณฑ์ว่าขั้นตอนนั้นผ่านหรือยัง — มักเป็นจำนวนแถว เมตริก หรือข้อความ `Lab N verification passed`  
ถ้าไม่ตรง ให้หยุดและแก้ก่อนไปขั้นถัดไป อย่าข้ามแล็บ

## fallback

ทางเลือกสำรองเมื่อเส้นทางหลักใช้ไม่ได้ เช่น notebook พยายามอ่านตาราง Lakehouse ก่อน ถ้ายังไม่มีจะอ่านไฟล์ CSV จาก `Files/raw/` แทน

## stratify

ตอนแบ่งชุดฝึก/ทดสอบ ให้สัดส่วนของคอลัมน์คำตอบ (เช่น อัตรา Churn) ในทั้งสองชุดใกล้เคียงกัน  
ใน Lab 3 ใช้ `stratify=y` เพื่อไม่ให้ชุดทดสอบมี churn น้อยหรือมากผิดปกติ

## random_state / seed

ค่าคงที่ที่ทำให้การสุ่มซ้ำได้ผลเดิมทุกครั้งที่รัน เช่น `random_state=42`  
ช่วยให้ทั้งคลาสได้จำนวนแถวและคะแนนใกล้เคียงกัน

## AUC (Area Under the ROC Curve)

คะแนนประมาณ 0 ถึง 1 วัดว่าโมเดล**แยกสองกลุ่ม**ได้ดีแค่ไหน โดยดูหลายจุดตัดความน่าจะเป็นพร้อมกัน

- ประมาณ 0.5 = ใกล้เดาสุ่ม  
- ใกล้ 1 = แยกได้ดี  

ใน FreshMart: ถ้าจัดอันดับลูกค้าตามความน่าจะเป็นที่จะเลิกซื้อ AUC สูงหมายความว่าลูกค้าที่เสี่ยงจริงมีแนวโน้มได้อันดับสูงกว่าคนที่ไม่เสี่ยง  
เหมาะเมื่อสัดส่วนสองกลุ่มไม่เท่ากัน (churn ประมาณ 19%) — อย่าดูแค่ Accuracy

## Accuracy

สัดส่วนทำนายถูกทั้งหมด  
หลอกได้ง่ายเมื่อกลุ่มหนึ่งมีน้อยมาก เช่น ทำนายว่า “ไม่ churn” เกือบทั้งหมดก็ได้คะแนนสูงโดยไม่จับลูกค้าเสี่ยง

## Precision / Recall

- **Precision** — ในที่โมเดลบอกว่า “ใช่ (จะ churn)” มีถูกกี่ส่วน; สำคัญเมื่อต้นทุนแคมเปญปลอมสูง  
- **Recall** — ในของจริงที่เป็น churn จับได้กี่ส่วน; สำคัญเมื่อพลาดลูกค้าเสี่ยงแล้วเสียหายมาก  
- **F1** — ค่าเดียวที่สมดุลระหว่าง Precision กับ Recall

## Overfitting

จำชุดฝึกได้ดีเกินไป แต่ทำนายข้อมูลใหม่หรือชุดทดสอบได้แย่

## Data leakage (ข้อมูลรั่วไหลเข้าโมเดล)

เอาข้อมูลที่ “รู้คำตอบล่วงหน้า” หรือสร้างจากคอลัมน์คำตอบไปฝึกโมเดล ทำให้คะแนนบนชุดทดสอบปลอมสูง แต่ใช้จริงไม่ได้

## Hyperparameter

ค่าตั้งของอัลกอริทึมที่คนเลือก**ก่อน**ฝึก เช่น จำนวนต้นไม้ ความลึกของต้นไม้  
ไม่ใช่ค่าที่โมเดลเรียนรู้เองจากข้อมูลระหว่าง `fit`

## Semantic Link

ไลบรารีเชื่อม Power BI Semantic Model กับโค้ด Python ใน Notebook เพื่อใช้ตัวชี้วัดธุรกิจชุดเดียวกับรายงาน

## Direct Lake

โหมดที่ Power BI อ่านตารางจาก OneLake โดยตรง โดยไม่ต้องโหลดข้อมูลซ้ำเข้าโมเดลแบบ Import
