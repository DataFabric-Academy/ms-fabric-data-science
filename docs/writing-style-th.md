# มาตรฐานภาษาไทยสำหรับ docs และ labs

ใช้เอกสารนี้เมื่อเขียนหรือแก้เนื้อหาใน `docs/` และ `labs/` เพื่อให้ผู้เรียน (โดยเฉพาะ Analyst) อ่านเข้าใจโดยไม่ต้องเดาตัวย่อ

## หลักการ

1. **ประโยคสมบูรณ์** — บอกว่าต้องทำอะไร เห็นอะไร และถ้าไม่ตรงให้ทำอะไรต่อ  
   - ไม่ดี: `จุดตรวจ: shape = (3000, 14)`  
   - ดี: `เมื่อรันถูกต้อง คุณควรเห็นจำนวนแถวประมาณ 3,000 และคอลัมน์ 14`

2. **ศัพท์เทคนิคครั้งแรก** — เขียนชื่อไทยแล้ววงเล็บอังกฤษ หรืออธิบายสั้น ๆ  
   - ตัวอย่าง: การสำรวจข้อมูลเบื้องต้น (Exploratory Data Analysis)

3. **คงภาษาอังกฤษเฉพาะเมื่อจำเป็น**  
   - ชื่อผลิตภัณฑ์: Microsoft Fabric, Power BI, OneLake, MLflow  
   - ป้ายบนหน้าจอ: **Data**, **Data Wrangler**, **Apply**, **Add code to notebook**  
   - ชื่อตาราง / ตัวแปร / ไฟล์: `bronze.transactions`, `feature_params.json`

4. **อย่าสร้างตารางอภิธานศัพท์ย่อยซ้ำในแต่ละแล็บ**  
   - อธิบาย 1–2 ประโยคในบริบทนั้น แล้วลิงก์ไป [glossary.md](glossary.md)

5. **ลดลูกศรยาว ๆ** ที่อ่านเป็นรหัส  
   - ไม่ดี: `EDA → Wrangler → MLflow → PREDICT`  
   - ดี: ลำดับเลข หรือประโยคเชื่อม เช่น “จากนั้น…” “ถัดไป…”

6. **คำถามทบทวน** — แต่ละข้อควรมีคำใบ้สั้น ๆ หรือลิงก์ไปบท/glossary ที่เกี่ยวข้อง (ไม่จำเป็นต้องเฉลยเต็ม)

## คำที่ใช้ในแล็บ

| ใช้คำนี้ | ความหมาย |
| --- | --- |
| สิ่งที่ควรเห็น | ผลที่คาดหวังหลังรัน (แทน “จุดตรวจ” อย่างเดียวถ้าต้องการความชัด) |
| โมเดลเส้นฐาน (baseline) | โมเดลแรกที่ใช้อ้างอิงเปรียบเทียบ |
| โมเดลที่เลือกใช้ (champion) | โมเดลที่ได้คะแนนดีที่สุดและลงทะเบียนไว้ |
| การทำนายเป็นชุด (batch scoring) | ทำนายหลายแถวตามรอบ ไม่ใช่ทีละคำขอทันที |

“จุดตรวจ” ยังใช้ได้ถ้าตามด้วยประโยคอธิบาย — ดู [glossary — จุดตรวจ](glossary.md#จุดตรวจ-verification)

## แม่แบบย่อหน้า “สิ่งที่ควรเห็น”

> หลังรันเซลล์นี้ ถ้าทุกอย่างถูกต้อง คุณควรเห็น …  
> ถ้าไม่ตรง ให้ … (ดู [อภิธานศัพท์](glossary.md))

## สิ่งที่ไม่เปลี่ยนตามมาตรฐานนี้

- ลำดับขั้นตอนแล็บและชื่อไฟล์ notebook  
- โค้ด Python และข้อความ `Lab N verification passed`  
- ชื่อตาราง / ค่าตัวเลขจุดผ่านจริงของชุดข้อมูล FreshMart
