## MLflow คืออะไร

**MLflow** เป็นเฟรมเวิร์กโอเพนซอร์สสำหรับบริหารวงจรชีวิตของการเรียนรู้ของเครื่อง — ใช้บันทึกว่าแต่ละครั้งที่ฝึกโมเดลตั้งค่าอะไร ได้คะแนนเท่าไร เก็บไฟล์โมเดลไว้เวอร์ชันไหน  
Microsoft Fabric รองรับ MLflow ในตัว: สร้าง Experiment, ดูการรันบนหน้าจอ และลงทะเบียนโมเดลใน workspace ได้โดยไม่ต้องติดตั้งเซิร์ฟเวอร์แยก

หลังจากมีตาราง `silver.customer_features` แล้ว งานถัดไปไม่ใช่แค่เรียก `model.fit()` แต่เป็นขั้นตอนที่ป้องกันข้อมูลรั่วไหลเข้าโมเดล, การจำชุดฝึกเกินไป (overfitting) และปัญหา “รันที่ดีที่สุดหาไม่เจอ”

## 6 ขั้นตอนมาตรฐาน

1. นิยามคอลัมน์คำตอบ (target) และวิธีวัดความสำเร็จทั้งทางธุรกิจและทางสถิติ  
2. แบ่งข้อมูลเป็นชุดฝึก / ชุดปรับแต่ง / ชุดทดสอบ  
3. เลือกอัลกอริทึมและค่าตั้งก่อนฝึก (hyperparameter)  
4. ฝึกโมเดลบนชุดฝึก (ปรับค่าบนชุดปรับแต่งตามกลยุทธ์)  
5. ประเมินบนชุดทดสอบ**ครั้งเดียว**เมื่อตัดสินใจเลือกโมเดล  
6. ลงทะเบียนโมเดลใน Model Registry พร้อมลายเซ็นโครงสร้างข้อมูล (signature)

การข้ามการแบ่งข้อมูลอย่างถูกต้องคือข้อผิดพลาดที่พบบ่อยและสร้างความมั่นใจปลอม

## การแบ่งชุดข้อมูล

| ชุด | หน้าที่ |
| --- | --- |
| **ชุดฝึก (Train)** | ให้โมเดลเรียนรู้จากตัวอย่าง |
| **ชุดปรับแต่ง (Validation)** | เลือกอัลกอริทึมหรือค่าตั้งก่อนฝึก |
| **ชุดทดสอบ (Test)** | ประเมินครั้งสุดท้าย — เสมือนข้อสอบที่ไม่เคยเห็น |

ชุดทดสอบห้ามใช้ตอนเติมค่าว่าง / ปรับสเกล / คัดฟีเจอร์แบบ “มองทั้งก้อน” โดยไม่แยกการคำนวณจากชุดฝึก

## Underfitting และ Overfitting

เป้าหมายคือโมเดลที่ทำนายข้อมูล**ใหม่**ได้ดี — ไม่ใช่คะแนนบนชุดฝึกสูงสุด

- **Underfitting**: โมเดลง่ายเกิน ผิดทั้งชุดฝึกและชุดทดสอบ  
- **Overfitting**: ดีมากบนชุดฝึก แต่พังบนชุดทดสอบหรือหน้างาน  

ใช้ชุดปรับแต่ง, จำกัดความซับซ้อนของโมเดล และเปรียบเทียบหลายการรันบนหลักฐานเดียวกัน

## เมตริก — เลือกให้สะท้อนธุรกิจ

### งานจำแนกประเภท (เช่น churn)

| เมตริก | วัดอะไร | ใช้เมื่อไร / ข้อควรระวัง |
| --- | --- | --- |
| **Accuracy** | สัดส่วนทำนายถูกทั้งหมด | หลอกได้ง่ายถ้า churn มีแค่ ~19% — ทำนายว่า “ไม่ churn” เกือบทั้งหมดก็ได้คะแนนสูง |
| **AUC (Area Under the ROC Curve)** | ความสามารถแยกสองกลุ่มตลอดหลายจุดตัดความน่าจะเป็น (คะแนนประมาณ 0.5 = เดาสุ่ม, ใกล้ 1 = แยกดี) | เหมาะเมื่อสัดส่วนสองกลุ่มไม่เท่ากัน และอยากดูภาพรวมคุณภาพการจัดอันดับความเสี่ยง |
| **Precision** | ในที่โมเดลบอกว่า “ใช่” มีถูกกี่ส่วน | สำคัญเมื่อต้นทุนแคมเปญปลอมสูง |
| **Recall** | ในของจริงที่เป็น “ใช่” จับได้กี่ส่วน | สำคัญเมื่อพลาดลูกค้าเสี่ยงแล้วเสียหายมาก |
| **F1** | สมดุลระหว่าง Precision กับ Recall | เมื่อต้องการค่าเดียวสรุปทั้งคู่ |

**สรุปสั้น ๆ เรื่อง AUC:** ถ้า FreshMart จัดอันดับลูกค้าตามความน่าจะเป็นที่จะเลิกซื้อ AUC สูงหมายความว่าลูกค้าที่เสี่ยงจริงมีแนวโน้มได้อันดับสูงกว่าลูกค้าที่ไม่เสี่ยง — ใช้เลือกโมเดลก่อนกำหนดเกณฑ์ตัดว่าใครเข้าแคมเปญ

### งานถดถอย / พยากรณ์ตัวเลข

| เมตริก | วัดอะไร |
| --- | --- |
| MAE | ค่าคลาดเคลื่อนสัมบูรณ์เฉลี่ย (หน่วยเดียวกับตัวแปร) |
| RMSE | คลาดเคลื่อนกำลังสองเฉลี่ยแล้วถอดราก — ลงโทษค่าผิดพลาดใหญ่ |
| MAPE | คลาดเคลื่อนสัมพัทธ์เป็นเปอร์เซ็นต์ |

ของเสียกับของหมดสต็อกมีต้นทุนไม่เท่ากัน — เลือกเมตริกและเกณฑ์ธุรกิจให้สอดคล้องต้นทุนจริง

ในแล็บนี้ Random Forest มักได้ AUC สูงกว่า Decision Tree อย่างมีนัย (ประมาณ 0.86 เทียบ 0.77 บน pipeline ท้องถิ่น)

## แนวคิดหลักของ MLflow บน Fabric

| แนวคิด | ความหมาย |
| --- | --- |
| **Experiment** | กล่องรวมการรันที่เกี่ยวข้องกัน |
| **Run** | การรันโค้ดฝึกหนึ่งครั้ง |
| **Params** | ค่าตั้งและค่าคงที่ (`log_param`) |
| **Metrics** | คะแนนวัดผล (`log_metric`) เช่น AUC |
| **Artifacts / Model** | ไฟล์โมเดลและข้อมูลประกอบ |
| **Registered Model** | เวอร์ชันพร้อมใช้ใน workspace |

Autologging ใน Fabric ช่วยจับพารามิเตอร์และเมตริกอัตโนมัติสำหรับไลบรารีที่รองรับ ลดโค้ดซ้ำ

## Model Registry

หลังเลือกโมเดลที่ดีที่สุด ([champion](glossary.md#โมเดลที่เลือกใช้-champion)) จากการเปรียบเทียบบนหน้า Experiment:

1. ลงทะเบียนเป็นรายการ ML Model ใน workspace  
2. เก็บหมายเลขเวอร์ชัน, เมตริก, สภาพแวดล้อม  
3. ใช้เวอร์ชันนั้นตอนสร้างคำทำนายเป็นชุด (M06)
